# Fast Player 4

这是 fast-player2 日志复盘后的“收益/风险平衡档”独立提交单元。默认产物为
`code/fast-player4/player.so`。

## 策略

- `vp=0`，u0 守中心、u1 主扫荡；根据守点单位的局部金币动态使用
  `k=0/2/3`，通常让主力先执行。
- u1 用 AVX2 扫描完整 5x5，u0 用标量扫描 3x3；目标靠近可见敌人时按
  35% 余值折价，并在冲突时重新扫描备选金币。
- 无目标时只在中心 3x3 附近移动 2-3 步；抵达金币后利用离开/重入重复
  拾取。
- 每轮最多扫描 7 个可见 NPC，屏蔽已有 3 个以上 NPC 的格子。
- 路线不主动进入迷雾、墙、已知炸弹、可见敌人或另一己方单位的预计占位。
  当目标或单位附近存在可见敌人时，还枚举一个“执行前已移动并静止”的未知
  阻挡格；若任一这种阻挡会使后续动作进入已知危险格，就退化为安全直线。

单静态阻挡模型比“每一步可独立随机阻挡”的模型更符合角色依次完整执行的
规则，也避免后者把大量正常回踩路线错误地压成停留。它没有覆盖两个隐藏角色
同时形成不同阻挡格的所有组合；NPC 和对手在我方后手时的最终位置也无法从
决策输入精确知道，仍需服务器回放验证。

## 构建与验证

从仓库根目录执行：

```bash
make -C code/fast-player4
make -C code/fast-player4 verify
make -C code/fast-player4 test
make -C code/fast-player4 sanitize
make -C code/fast-player4 bench
make -C code/fast-player4 compare
make -C code/fast-player4 replay
```

Release 使用 C++17、`-O3 -DNDEBUG -flto -march=x86-64-v3`。`test`
默认运行 50,000 个确定性模糊输入，并额外检查可见 3+ NPC 回避和单静态
阻挡下的路径安全。`compare` 以 fast-player2 为延迟参照；本版有额外安全
逻辑，默认上限为 fast-player2 P90 的 3.50 倍。

## 当前本地结果

开发机为 Intel Xeon Platinum 8255C。固定 CPU 后，Release 版本每轮
1,000,000 次调用、共 5 轮：

- P50 0.292-0.299 us；
- P90 0.490-0.500 us；
- P99 0.701-0.786 us；
- 最大值 25.920-232.563 us，最大值为调度离群点；首次调用 4.144 us。

同一次交错测量中，fast-player2 P90 为 0.185 us，fast-player4 为
0.492 us，比值 2.662。它不是速度冠军，但仍远低于 200 us；上述均为本地
实测，不是赛事服务器成绩。

对 26 局、13,000 回合旧输入的反事实回放：

| 指标 | fast-player2 | fast-player4 |
| --- | ---: | ---: |
| 可见拾取代理 | 46,921 | 41,427 |
| 可见 3+ NPC 踩踏损失 | 1,369 | 0 |
| 慢手折价净代理 | 41,350 | 38,111 |
| 成功移动步数 | 50,519 | 50,923 |

因此本版保留 fast-player2 的 88.3% 毛拾取代理和 92.2% 可见风险后净代理，
同时消除回放中当前可见的踩踏损失。反事实回放不能重建路线变化后的视野、
对手/NPC 响应或最终胜率，必须以新服务器日志复测。
