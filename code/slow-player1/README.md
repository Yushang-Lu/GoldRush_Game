# Slow Player 1

这是独立于其他目录的“高算力、默认后手”策略，提交产物为
`code/slow-player1/player.so`。默认每次合法调用使用约 `240 ms` 的有界
anytime 搜索；它刻意远慢于公开日志中的常见策略，但给官方 `300 ms` 单轮门槛
保留约 `60 ms` 调度余量。若机器发生长时间抢占，仍可能越过门槛；这是故意变慢
不可消除的风险。

## 策略结构

- 累积已见静态地形、金币证据、炸弹周期内证据、访问新旧程度、阻挡证据、区域
  快照、敌方匿名轨迹和按 ID 管理的 NPC 概率分布。第 0 轮、轮数回退或跳变会
  完整重置。
- 用公开日志中的四张障碍图和高额外围点作为可撤销先验。每个已见格都核对全部
  候选模板；发生一个冲突即删除相应模板，全部冲突后只使用亲眼观察的通用地图。
- 完整枚举 `5^6 * 7 * 2 = 218,750` 个动作/分步/执行顺序组合，按 65% 向上
  取整、己方顺序占位、墙/边界、炸弹、NPC 踩踏、可见与历史金币、探索价值和
  区域分工做第一阶段筛选。
- 生成 96 个“快方先走、NPC 再走、我方后走”的随机情景。敌方与 NPC 会按
  概率位置、金币竞争、未知墙、金币存活和炸弹是否被提前触发演化；保留均值、
  方差和最差 20% 尾部表现，领先时提高下行风险权重。
- 对 36 个决赛候选持续做 7–12 轮随机 rollout，模拟中心持续产币、外围高额
  事件、20 轮炸弹刷新、敌方/NPC 抢币、后手路径和未来联合采集，直到时间预算
  到期。PRNG 由输入和对局序号确定，不使用 `random_device`。
- 视野购买按下一轮新增信息的预期价值决定，并限制累计费用；第 499 轮不会购买。

## 日志先验的边界

仓库中 40 局、20,000 回合公开日志显示四张底图；中心区持续生成，外围高额
事件在快照中约隔 5–20 轮出现、单次总量约 100–140。NPC 动作分布不支持把
其策略写死。因此这些数字只用于情景分布，绝不当作官方未公开规则；新地图或新
分布会依靠观察与快照逐步替换先验。

## 构建与验证

```bash
make -C code/slow-player1
make -C code/slow-player1 verify
make -C code/slow-player1 test
make -C code/slow-player1 sanitize
make -C code/slow-player1 bench
```

默认 Release 参数包含 C++17、`-O3 -DNDEBUG -fPIC -shared -flto`，没有
`-march=native`。可用 `THINK_US` 显式调整提交库的思考预算，例如：

```bash
make -C code/slow-player1 clean
make -C code/slow-player1 THINK_US=220000
```

测试和 sanitizer 构建把时间预算设为 0，并对动作空间做确定性分层抽样，从而
能够执行连续 500 轮、边界用例和随机模糊测试；Release 提交库仍使用完整枚举与
定时 rollout。`bench` 直接通过 `dlopen` 测量同一个 Release `player.so`。
默认只测 100 次乘 2 轮，因为 50,000 次在 240 ms 预算下约需 3.3 小时；可用
`BENCH_SAMPLES` 和 `BENCH_RUNS` 覆盖。

## 已知风险

- 官方没有模拟器，rollout 中的 NPC policy、隐藏地图、随机生成和炸弹重采样
  都是公开信息下的概率模型，不是事实。
- 双方在行动前收到同一状态；后手并不会看到快方的新动作。慢策略的价值只来自
  更多计算和“金币可能已被取走/位置可能被占”的鲁棒规划，后手本身通常会损失
  抢币优先级。
- 240 ms 会让一局墙钟时间很长，也比普通策略更接近 300 ms 判负边界。赛事机
  成绩和稳定性必须由真实提交验证。
