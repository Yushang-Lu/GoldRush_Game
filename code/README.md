# GoldRush 2.0 C++ 策略

## 策略概览

`player.cpp` 是一个固定计算上界、无堆分配的双角色联合策略：

- 每名角色只扫描本轮可见的 5x5 邻域，并按 65% 向上取整的规则估算
  一至三次重复进入金币格的收益。
- 联合比较常规 `k=1..5` 的六步分配；若另一角色没有局部机会，而第六步能
  产生至少 2 金币的额外确定收益，也会采用合法的 `k=0/6`。高收益角色获得
  先执行权；第一条路线先更新金币余量，另一角色随后重新选目标，避免双方
  争抢同一份余币。
- 路线优先即时金币；到达目标后会离开再进入以继续拾取。无局部目标时，
  两个角色向中心 9x9 的错开巡逻点移动，因为规则明确金币主要逐轮生成于中心。
- 有效快照显示某个外围区域的单位面积净资源显著优于中心时，一名角色短期改去
  该区域；这里只使用公开区域统计作为宏观方向，不把它伪装成精确格子信息。
- 连续两次出现“路径预计有可见收益、下一轮持币却没有对应增长”后，策略把
  自己视为大概率慢手：可见敌人/NPC 本格及相邻格的金币先按已被拾取一口折价，
  再做目标和步数分配。该反馈不把炸弹/踩踏造成的负增长误判成慢手证据。
- 当前 20 回合周期内见过的炸弹用紧凑位图保存；当前可见敌人、3 个以上 NPC
  的格子及历史炸弹均不得进入。墙只使用本轮权威视野，不把旧地形当成当前视野；
  持币达到 200 后不主动进入迷雾。
- 不购买视野。三份新日志中双方都未购买，且当前局部规划只消费默认 5x5 信息；
  在没有扩大搜索范围前盲买只会增加终局净成本。
- 新对局、回合回退或非连续调用会重置历史和慢手状态；所有异常输入返回 6 个显式
  “不动”动作。策略不使用未公开地图、NPC 策略或隐藏对手身份信息。

相较于 `info/player2.cpp`，本版保留了更紧凑的 4 字节局部候选和动态己方执行
顺序，并借鉴其最有日志依据的慢手反馈/竞争折价。地图观察与金币扫描合并为一遍，
压力标记只在实际金币候选上结算；联合路线只保存至多六个金币差分。没有移植其
高开销敌方终点、五轮敌位和全图 NPC 三步可达预测，而是用抢先手降低这些风险。

## 构建与验证

```bash
make                 # Release 构建 player.so
make test            # 场景测试 + 50,000 个确定性随机输入
make sanitize        # ASan/UBSan + 20,000 个随机输入
make bench           # 3 轮，每轮 50,000 次 Release 调用
make versus LOGS='../logs/*.log'
                     # 编译 info/player2.cpp，回放日志并做交叉性能验收
make clean
```

`versus` 要求候选在同一进程、前后交叉顺序的 100,000 样本测试中，平均 P90
不高于 `info/player2.cpp` 的 95%。日志回放同时报告原始可见收益和一个慢手模型：
只有日志确认 P1 后手时，才把可见敌人/NPC 邻格金币折价一口。三份日志上该模型
比未折价预测更接近实际拾金，但隐藏行动和改变决策后的地图演化仍无法重建；它是
校准过的策略回归，不是胜率模拟器，也不能证明必胜。

默认 Release 参数为 C++17、`-O3 -DNDEBUG -fPIC -flto`，使用固定的
`-march=x86-64-v3`（官方 FAQ 公布的 AMD EPYC 指令集覆盖该级别），不使用
本机相关的 `-march=native`。最终提交物是 `code/player.so`，仍应在赛事提供的
AMD EPYC 编译机重新构建、复测依赖和实战对局。当前容器运行在 ptrace 监控下，
LeakSanitizer 无法启动，所以 `make sanitize` 关闭 LSan；ASan 与 UBSan 仍启用。
