# GoldRush 2.0 C++ 策略

## 策略概览

`player.cpp` 实现了一个有固定计算上界的双角色联合策略：

- 记忆已确认的墙体、探索时间戳和当前 20 回合刷新周期内的炸弹；只追逐本轮明确可见的金币，不把迷雾或陈旧金币当作确定信息。
- 每轮使用六步固定上界的局部规划；在可见目标数量适中时做两步金币前瞻，不使用会抬高 P90 尾部的周期性 BFS。
- 联合比较 `k=0/3/6` 三种步数分配并精确回放两个角色的占位、剩余金币和风险；已知炸弹及 3 个以上 NPC 的格子不会进入候选路径。
- 目标和局部前瞻权重由五局日志的离线反事实回放筛选；联合估值包含 65% 向上取整拾取、探索新鲜度、区域快照、角色分散和保守视野购买，并保持无堆分配的固定上界。
- 记忆本轮 20 回合炸弹刷新周期内确认过的炸弹，即使它转入迷雾也按风险回放；新刷新周期不沿用旧炸弹推断。
- 视野购买采用保守规则：附近缺少目标且信息陈旧时才购买，并跟踪已支付成本；购买结果按规则于下回合生效。
- 新对局、回合回退或非连续调用会重置历史状态；所有异常输入路径均返回 6 个显式“不动”动作。

本次分析的五局同地图日志中，旧版本在三局慢对手面前全程先手、两胜一负；在 P90 为 0.4 与 12.84 微秒的两个快对手面前全程后手、两局均负。最终版本的日志反事实回放把可见即时拾金从 11,657 提升到 11,892（+2.0%），已知风险损失从 10 降到 0，逐回合即时价值比较为 464 次更好、278 次更差、1,758 次相同。它仍不是完整模拟器，不能直接证明真实胜率；NPC 策略、隐藏对手行动和因先后手改变导致的地图演化无法从输入重建。

## 构建与验证

```bash
make                 # Release 构建 player.so
make test            # 场景测试 + 50,000 个确定性随机输入
make sanitize        # ASan/UBSan + 20,000 个随机输入（当前环境关闭 LSan）
make bench           # 3 轮，每轮 50,000 次 Release 调用
make logs            # 汇总 ../logs/*.log 的赛果、延迟、先手和资源指标
make compare BASELINE_SO=/path/to/old.so PERF_RATIO=0.05
                     # 同时回放并检查新旧本地 P90 比率
make clean
```

日志是 JSON Lines：第一行为玩家信息，第二行为完整底图，其后每行一个回合。读取和回放工具位于 `tools/`，只用于离线开发，不会进入策略热路径。若要把当前版本与某个旧 `.so` 比较：

```bash
make replay BASELINE_SO=/path/to/previous-player.so LOGS='../logs/*.log'
```

该回放只比较输入中可以确定的可见拾金、已知/仍在刷新周期内的历史炸弹、入雾和阻挡；它不会伪造隐藏的敌方或 NPC 行动，因此是策略质量回归而不是胜率模拟。`compare` 在比率不达标时返回非零。当前容器对 100,000 样本进行旧版/候选交叉顺序测量，三次独立比较的 P90 比率为 0.044、0.048、0.043；候选单库五轮 P90 为 2.780、2.670、2.679、2.660、2.710 微秒。以上均是本机微基准，不是赛事服务器成绩。

默认 Release 参数为 C++17、`-O3 -DNDEBUG -fPIC -flto`，没有使用本机 `-march=native`。最终提交物是 `code/player.so`，仍应在赛事提供的编译机上重新构建并检查依赖与实战回放。

当前工作容器运行在 ptrace 监控下，LeakSanitizer 无法启动，因此
`make sanitize` 设置 `detect_leaks=0`；AddressSanitizer 和
UndefinedBehaviorSanitizer 仍然启用。策略热路径不进行堆分配。
