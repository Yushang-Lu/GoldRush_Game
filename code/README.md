# GoldRush 2.0 C++ 策略

## 策略概览

`player.cpp` 是一个固定计算上界、无堆分配的双角色联合策略：

- 每名角色只扫描本轮可见的 5x5 邻域，并按 65% 向上取整的规则估算
  一至三次重复进入金币格的收益。
- 联合比较 `k=1..5` 的六步分配；高收益角色获得更多步，角色 0 的路线会
  和先执行权；第一条路线先更新金币余量，另一角色随后重新选目标，避免双方
  争抢同一份余币。
- 路线优先即时金币；到达目标后会离开再进入以继续拾取。无局部目标时，
  两个角色向中心 9x9 的错开巡逻点移动，因为规则明确金币主要逐轮生成于中心。
- 有效快照显示某个外围区域的单位面积净资源显著优于中心时，一名角色短期改去
  该区域；这里只使用公开区域统计作为宏观方向，不把它伪装成精确格子信息。
- 已知墙和当前 20 回合周期内见过的炸弹用紧凑位图保存；当前可见敌人、
  3 个以上 NPC 的格子及历史炸弹均不得进入。持币达到 200 后不主动进入迷雾。
- 不购买视野。当前唯一实战日志中旧策略支付 100 金视野费却仍长期慢手；本版
  把这部分净成本和购买分支都移除。
- 新对局、回合回退或非连续调用会重置历史状态；所有异常输入返回 6 个显式
  “不动”动作。策略不使用未公开地图、NPC 策略或隐藏对手身份信息。

相较于用户提供的 `info/player.cpp`，本版复用了它最有效的局部采金、重复拾取、
动态步数分配和中心巡逻思路，但没有携带其慢手专用预测器。工程上只更新两个
当前视野窗口，持久地图使用位图，联合路线只保存至多六个金币差分。

## 构建与验证

```bash
make                 # Release 构建 player.so
make test            # 场景测试 + 50,000 个确定性随机输入
make sanitize        # ASan/UBSan + 20,000 个随机输入
make bench           # 3 轮，每轮 50,000 次 Release 调用
make versus LOGS='../logs/*.log'
                     # 编译 info/player.cpp，回放日志并做交叉性能验收
make clean
```

`versus` 要求候选在同一进程、前后交叉顺序的 100,000 样本测试中，平均 P90
严格低于 `info/player.cpp`。日志回放只比较输入中可以确定的可见拾金、已知及
本炸弹周期内的历史炸弹、入雾和阻挡；隐藏敌方/NPC 行动和先后手改变后的地图
演化无法重建，因此它是策略质量回归，不是胜率模拟器，也不能证明必胜。

默认 Release 参数为 C++17、`-O3 -DNDEBUG -fPIC -flto`，不使用本机
`-march=native`。最终提交物是 `code/player.so`，仍应在赛事提供的 AMD EPYC
编译机重新构建、复测依赖和实战对局。当前容器运行在 ptrace 监控下，
LeakSanitizer 无法启动，所以 `make sanitize` 关闭 LSan；ASan 与 UBSan 仍启用。
