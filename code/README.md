# GoldRush 2.0 C++ 策略

## 策略概览

`player.cpp` 实现了一个有固定计算上界的双角色联合策略：

- 记忆已确认的墙体、最近看到的金币及信息时间戳；不会把迷雾当空地。
- 用固定宽度束搜索为每个角色生成 0 到 6 步候选，再联合枚举分割点、候选组合和执行顺序；联合回放仅保留每组最优的两个候选，以压低先手延迟。
- 联合回放会处理边界、墙、可见敌人、己方角色占位、金币余量、炸弹及 3 个以上 NPC 的踩踏风险。
- 估值包含 65% 向上取整拾取、10% 炸弹损失、5% 踩踏损失、探索价值、区域快照、目标竞争和双角色分散。
- 记忆本轮 20 回合炸弹刷新周期内确认过的炸弹，即使它转入迷雾也按风险回放；新刷新周期不沿用旧炸弹推断。
- 视野购买采用保守规则：附近缺少目标且信息陈旧时才购买，并跟踪已支付成本；购买下回合才生效。
- 新对局、回合回退或非连续调用会重置历史状态；所有异常输入路径均返回 6 个显式“不动”动作。

策略已用两份同地图、同对手的 500 回合日志校准。日志显示本策略在两局中均以约 69 微秒的服务端 P90 先于约 322 微秒的对手行动；一胜一负。优化以日志输入的反事实回放约束即时可见拾金与已知风险，但这不是完整模拟器，不能直接推出新版本胜率。NPC 策略、金币分布和隐藏对手行动仍无法从输入完全得知。

## 构建与验证

```bash
make                 # Release 构建 player.so
make test            # 场景测试 + 50,000 个确定性随机输入
make sanitize        # ASan/UBSan + 20,000 个随机输入（当前环境关闭 LSan）
make bench           # 3 轮，每轮 50,000 次 Release 调用
make logs            # 汇总 ../logs/*.log 的赛果、延迟、先手和资源指标
make clean
```

日志是 JSON Lines：第一行为玩家信息，第二行为完整底图，其后每行一个回合。读取和回放工具位于 `tools/`，只用于离线开发，不会进入策略热路径。若要把当前版本与某个旧 `.so` 比较：

```bash
make replay BASELINE_SO=/path/to/previous-player.so LOGS='../logs/*.log'
```

该回放只比较输入中可以确定的可见拾金、已知/仍在刷新周期内的历史炸弹、入雾和阻挡；它不会伪造隐藏的敌方或 NPC 行动，因此是策略质量回归而不是胜率模拟。

默认 Release 参数为 C++17、`-O3 -DNDEBUG -fPIC -flto`，没有使用本机 `-march=native`。最终提交物是 `code/player.so`，仍应在赛事提供的编译机上重新构建并检查依赖与实战回放。

当前工作容器运行在 ptrace 监控下，LeakSanitizer 无法启动，因此
`make sanitize` 设置 `detect_leaks=0`；AddressSanitizer 和
UndefinedBehaviorSanitizer 仍然启用。策略热路径不进行堆分配。
