# Final Player

最终提交产物是 `code/final-player/player.so`。本目录是独立构建单元，不会覆盖
其他策略目录。

## 策略

最终版采用首轮地图指纹切换：

- 已知三类旧地图及其他低墙密度地图走 `fast-player2` 极速档。旧日志 13,000
  回合的 `actions/k/order/vp` 已逐字段验证为完全相同，因此保留旧图上的速度
  和已实战轨迹。
- 新日志迷宫在首轮两角视野中有 6 面墙，进入拓扑深搜档。策略使用日志公开的
  静态墙图和六个反复出现高额余币的外围格点；后续每轮核对新看到的墙，一旦
  与指纹冲突就立即丢弃未亲眼确认的硬编码地形，退回通用历史地图搜索。
- 首轮墙较多但不匹配已知迷宫的未知地图也进入通用深搜档，只把实际观察过的
  地形作为已知信息，不把迷雾当空地。

深搜档的每轮决策：

- 保存静态地形、最近可见值、炸弹刷新周期内的已知炸弹、访问时间、金币证据和
  最新合法区域快照；新局、轮数回退或跳变都会重置状态。
- 一个单位负责外围热点，结合快照余币、occupants、实际可见金币、历史证据和
  BFS 距离动态换点；另一个单位覆盖中心 9x9 的金币和低访问巡逻点。
- 固定 3+3 分步。对每个单位枚举全部 `5^3=125` 条三步动作，保留 8 条最高
  估值路线以及必要的单步让路/全停锚点，再联合评估最多 `8x8x2` 个路线与
  `order` 组合。
- 联合模拟严格执行 65% 向上取整的重复拾取、两个己方角色依次行动、最终占位、
  当前可见敌人、墙、边界、已知炸弹和 NPC 踩踏；可预见的己方碰撞组合直接
  淘汰。
- 保存计划终点。下一轮实位若不一致，说明之前有外部角色改变了执行结果；随后
  临时只保留在任意一个静态阻挡格下仍不会走入已知墙/炸弹的动作前缀，证据消退
  后恢复完整回踩搜索。
- `vp` 恒为 0，不承担不可见的终局费用；热路径无日志、文件 I/O、堆分配或
  随机数。

没有采用“故意变慢以确保后手”：双方输入在角色行动前已经固定，主动让出先手
不会获得新信息。`always_deep` 候选保留了更宽的搜索，用来检验计算量与路线
质量的权衡。

## 保留的候选

| 源文件 | 用途 |
| --- | --- |
| `candidates/fast_only.cpp` | 所有地图强制使用原极速策略 |
| `candidates/always_deep.cpp` | 所有地图使用 28 路宽搜索 |
| `candidates/adaptive_no_hotspots.cpp` | 地图切换和深搜，但不利用特殊图外围高额点 |
| `candidates/adaptive_no_block_inference.cpp` | 最终规划器，但关闭跨轮阻挡证据；用于同输入反事实审计 |

`make candidates` 会分别生成同名 `.so`。这些候选不会被最终入口引用，保留是
为了后续真实对局能够继续做 A/B 测试，而不是凭直觉删除失败路线。

## 构建与验证

从仓库根目录执行：

```bash
make -C code/final-player
make -C code/final-player candidates
make -C code/final-player verify
make -C code/final-player test
make -C code/final-player sanitize
make -C code/final-player bench
make -C code/final-player regression
make -C code/final-player report
make -C code/final-player simulate
```

- `test`：定向覆盖全迷雾、角落、已知墙/炸弹、金币、可见敌人、0-7 NPC、
  合法/非法快照、500 连续回合、换局、轮数回退/跳变、后手阻挡安全前缀，
  另运行 50,000 个确定性随机输入。
- `sanitize`：ASan/UBSan 独立构建并运行 20,000 个随机输入；不用于计时。
- `bench`：分别测极速分支和闭环迷宫分支。样本数可用
  `SPARSE_SAMPLES`、`DENSE_SAMPLES`、`BENCH_RUNS` 覆盖。
- `regression`：把最终库与 `fast-player2` 在全部旧日志逐字段比较。
- `report`：逐条打印新日志实战统计与同输入反事实指标。
- `simulate`：运行缺少对手/NPC/炸弹的简化迷宫覆盖代理，只用于候选相对筛选。

Release 参数为 C++17、`-O3 -DNDEBUG -flto -fPIC -shared`、隐藏非 ABI
符号并使用 `-march=x86-64-v3`。官方 FAQ 所列运行 CPU 支持 AVX2；最终库
通过版本脚本只导出 `moveDecision`。

## 当前离线结果

- 旧日志回归：13,000/13,000 回合与 `fast-player2` 完全一致。
- 新日志同输入、关闭阻挡推断以隔离规划器影响：可见拾币代理
  `14,782 -> 29,905`，当前可见踩踏代理 `1,218 -> 7`，移动
  `19,537 -> 39,222`。
- 30 个固定种子的简化迷宫代理：`fast-player2` 平均 3233.9，最终版平均
  8173.0；该数字不是官方引擎金币或胜率。
- 本机稀疏分支 100,000 次 x 3 轮：P50 0.162-0.166、P90
  0.209-0.223、P99 0.295-0.342 微秒，最大 52.394 微秒，首次调用
  7.051 微秒。
- 本机闭环迷宫分支 50,000 次 x 3 轮：P50 37.695-37.826、P90
  43.439-47.115、P99 57.926-59.496 微秒，最大 298.075 微秒，首次
  调用 57.994 微秒。三轮 P90 都低于 200 微秒目标，最大值是未进入 P99
  的调度离群点。
- 测量机器为 4 vCPU Intel Xeon Platinum 8255C，Linux 6.8 x86-64，
  编译器为 g++ 13.3.0；参数与上文 Release 提交构建一致。以上都只是本地
  实测，不是赛事服务器成绩。

详细日志依据和逐局判读见 [ANALYSIS.md](ANALYSIS.md)。

## 尚未验证

- 没有官方模拟器，反事实回放不能生成候选改变路线后的视野、对手和 NPC 响应。
- 简化迷宫代理不包含真实对手、NPC 策略、炸弹和未公开随机分布，不能代替新
  服务器对局。
- 特殊图的墙和六个热点来自本批公开日志；虽有逐轮指纹降级保护，另一张地图若
  共享首轮角落布局，确认冲突前的少数动作仍可能使用错误先验。
- 本地 CPU 和赛事机不同，延迟最终以服务器为准；真实策略强度尤其需要针对
  `player369/player392/player408` 类高收益慢策略，以及更快对手造成的窄道
  阻挡重新复测。
